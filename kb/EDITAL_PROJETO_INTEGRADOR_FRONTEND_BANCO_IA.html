01 / Edital

O que precisa ser construído

O tema é livre; os requisitos técnicos não são opcionais. Um jogo, uma plataforma de serviços e um site de eventos podem cumprir a mesma avaliação.

Missão obrigatória: demonstrar um fluxo ponta a ponta: interface React → API/servidor → banco de dados → resposta na tela, com ao menos uma funcionalidade de IA real pertinente ao propósito. O sistema deve funcionar após recarregar a página e ser acessível por um link publicado.

Front-end

Interface que alguém consegue usar

React, navegação funcional, formulário, listagem, interface responsiva, tratamento de loading/erro e atenção à acessibilidade. Interface bonita é importante, mas não substitui funcionalidade.

Banco e backend

Persistência e relações reais

Três tabelas, duas FKs, CRUD demonstrável, consultas SQL relevantes e um índice analisado. O servidor valida entradas, protege segredos e se comunica com o banco relacional.

Inteligência artificial

Um ganho concreto para o usuário

Uma chamada verdadeira a um modelo/API, com um caso de uso ligado ao produto. Mostrar o antes/depois da funcionalidade: qual tarefa a IA torna mais fácil, rápida ou compreensível?

Obrigações gerais

  • Equipe: trios; todos participam do código e da apresentação.
  • Entrega única: mesmo repositório para frontend, backend, SQL e documentação.
  • Sem pagamento: compra simulada pode existir, mas transação real não é exigida.
  • Dados: usar apenas cadastros fictícios.
  • Infraestrutura: soluções gratuitas ou disponíveis para o grupo; gasto obrigatório não é permitido.

O que NÃO será pedido

  • Login complexo, múltiplos perfis ou pagamentos reais.
  • Chatbot genérico desconectado do objetivo do produto.
  • Milhares de usuários, app mobile nativo ou microsserviços.
  • Treinar um modelo de IA do zero.
  • Modelos enormes, hospedagem paga ou design de agência.

Regra de escopo: faça um fluxo completo e simples antes de acrescentar extras.

Importante: a proposta anterior de AV3 exigia o tema “venda de produto”. Nesta versão, a escolha temática foi ampliada por orientação do professor para jogo, sistema ou site. Os demais requisitos acadêmicos de Banco de Dados, colaboração e defesa foram mantidos como referência.

02 / Inspiração com limites claros

Escolha uma ideia que caiba em 14 dias

Projetos viáveis têm um problema simples, um banco pequeno, um fluxo principal e uma IA com propósito. Estes exemplos não são modelos obrigatórios.

Sistema

Central de chamados estudantis

Usuário faz: registra problema, consulta situação e atualiza um chamado.

Dados: categorias → chamados → interações.

IA útil: propõe categoria, prioridade e resumo para triagem, sempre com confirmação humana.

MVP: 3 telas + 1 sugestão automática

Jogo

Quiz adaptativo com histórico

Usuário faz: responde desafios e vê desempenho.

Dados: jogadores fictícios → partidas → respostas.

IA útil: explica o erro e sugere uma dica ligada ao desafio escolhido.

MVP: jogar 5 questões, salvar tentativas e pedir dica

Site

Catálogo de oficinas/eventos

Usuário faz: consulta eventos e registra uma inscrição fictícia.

Dados: categorias → eventos → inscrições.

IA útil: sugere a oficina mais adequada a objetivos descritos pelo visitante.

MVP: lista, formulário, painel de inscrições

Sistema

Organizador de estudos

Usuário faz: cria atividades e acompanha conclusão.

Dados: disciplinas → atividades → registros de estudo.

IA útil: transforma uma atividade longa em passos menores, sem prometer previsão infalível.

MVP: criar tarefa, mudar status, consultar progresso

Serviço

Guia de manutenção

Usuário faz: cadastra equipamento fictício e solicita manutenção.

Dados: equipamentos → solicitações → atualizações.

IA útil: transforma relato confuso em checklist de atendimento seguro.

MVP: registro + histórico + checklist sugerido

Site

Biblioteca de recomendações

Usuário faz: avalia materiais e navega por categorias.

Dados: categorias → materiais → avaliações.

IA útil: resume opiniões cadastradas, deixando claro quando são poucas.

MVP: catálogo + avaliação + resumo contextual

Exemplo que NÃO atende: uma página bonita com texto estático, itens em array local, chat que responde com frases prontas e link de Vercel. Isso não prova banco de dados nem integração real de IA.

03 / Arquitetura sem mistério

Um desenho vale mais que dez bibliotecas

O segredo para integrar as disciplinas é saber onde cada parte roda e quem pode acessar informações privadas.

Camada visível · browser do usuário
React → formulário/listagem → fetch('/api/...')

A interface captura ações e mostra respostas, erros e estados. Nunca armazena senha do banco nem chave privada da IA.

Camada protegida · servidor (Vercel)
Route Handler → validação → SQL / provedor de IA

O servidor recebe os dados, valida, usa variáveis de ambiente e retorna somente o necessário ao React.

Caminho A — recomendado para facilitar

Next.js (React) + Route Handlers + PostgreSQL/Neon + Vercel. Permite uma única aplicação e um único deploy, com front e API integrados. Menos configurações de CORS e hospedagem separada.

Recomendação de engenharia para o prazo; não exige que o grupo abandone stacks que já dominam.

Caminho B — também aceito

React/Vite + Node/Express (ou Flask/FastAPI) + banco relacional. O backend precisa estar acessível por HTTPS em produção; publicar só o frontend no Vercel não basta.

Caso escolham esta opção, documentar URLs e configurar CORS/origens corretamente.

04 / Tutorial para começar do zero

Do problema ao primeiro registro salvo

Siga a ordem. O grupo que faz o deploy só no último dia normalmente descobre problemas tarde demais.

1

Escolham problema, usuário e uma tarefa principal

Completem em uma frase: “Nosso aplicativo ajuda [público] a [ação] porque hoje [dificuldade].” Identifiquem o caminho que precisa funcionar até o final. Exemplo: criar um chamado → salvar → listar → alterar status → solicitar ajuda da IA.

Evitem: colocar IA primeiro e procurar uma utilidade para ela depois.

2

Desenhem as três tabelas e os fluxos

Rascunhem as telas no papel e usem setas para representar PK/FK. Cada campo deve ter um motivo. Definam também o que será enviado ao modelo e qual dado pode ser compartilhado (sempre fictício).

Exemplo SQL (PostgreSQL) — 3 tabelas e 2 FKs
CREATE TABLE categorias (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  nome VARCHAR(80) NOT NULL UNIQUE
);

CREATE TABLE chamados (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  categoria_id BIGINT NOT NULL REFERENCES categorias(id),
  titulo VARCHAR(120) NOT NULL,
  descricao TEXT NOT NULL,
  status VARCHAR(20) NOT NULL DEFAULT 'aberto'
    CHECK (status IN ('aberto','andamento','concluido')),
  criado_em TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE interacoes (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  chamado_id BIGINT NOT NULL REFERENCES chamados(id),
  mensagem TEXT NOT NULL,
  criado_em TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

As tabelas são exemplo de raciocínio, não tema obrigatório. Os grupos adaptarão os nomes e relações.

3

Criem o projeto React

Instalem Node LTS e VS Code. No terminal do VS Code, usem a opção recomendada. A criação exige internet. Respondam às perguntas do assistente de modo coerente com o grupo. Depois abram a pasta criada e executem a aplicação localmente.

Terminal do VS Code
npx create-next-app@latest projeto-integrador --ts --eslint --app --use-npm
cd projeto-integrador
npm run dev

Abram http://localhost:3000. Se esse comando falhar por Node incompatível, atualizem para uma versão LTS compatível indicada pelo próprio Next.js.

4

Criem GitHub e comecem os commits

Um único repositório por trio. Convidem os colegas e validem que todos conseguem contribuir. O create-next-app pode criar Git automaticamente: confiram antes de reinicializar.

Terminal Git — após criar repo vazio no GitHub
git status
git add .
git commit -m "chore: inicia projeto integrador"
git branch -M main
git remote -v
# Se NÃO houver remote origin:
git remote add origin URL_DO_REPOSITORIO
git push -u origin main

Caso o projeto já tenha commit inicial, git commit poderá informar que não há mudanças — não é erro. Substituam a URL; não copiem o texto URL_DO_REPOSITORIO literalmente.

5

Conectem o banco ao servidor, nunca ao cliente

Para quem escolher Neon/PostgreSQL, criem projeto no painel, copiem a string de conexão somente para .env.local, executem seu SQL no editor de consultas do banco e instalem o driver no projeto. A leitura/gravação deve ocorrer em código do servidor (Route Handler).

Terminal e arquivos de configuração
npm install @neondatabase/serverless

# .env.local (SOMENTE NA MÁQUINA, NÃO PUBLICAR)
DATABASE_URL="postgresql://USUARIO:SENHA@HOST/BANCO?sslmode=require"
AI_API_KEY="CHAVE_PRIVADA_DA_API"

# .env.example (PODE IR AO GITHUB)
DATABASE_URL=
AI_API_KEY=

São exemplos de nomes de variáveis, não credenciais reais. Confiram que .env.local está no .gitignore e não aparece no git status.

6

Construam o primeiro endpoint funcional

Em Next.js App Router, criem src/app/api/chamados/route.ts se escolheram estrutura src/; do contrário, usem app/api/chamados/route.ts. Um GET lê dados reais, um POST valida e grava. Evitem concentrar lógica de produção em componentes React.

Exemplo mínimo de GET com Neon (Next.js)
import { neon } from '@neondatabase/serverless';

export const runtime = 'nodejs';

export async function GET() {
  const url = process.env.DATABASE_URL;
  if (!url) {
    return Response.json({ erro: 'Banco não configurado' }, { status: 503 });
  }
  try {
    const sql = neon(url);
    const dados = await sql`SELECT id, titulo, status
                            FROM chamados ORDER BY id DESC LIMIT 50`;
    return Response.json(dados);
  } catch {
    return Response.json({ erro: 'Falha ao consultar dados' }, { status: 500 });
  }
}

Teste: acesse http://localhost:3000/api/chamados. Esse exemplo só lê; o grupo ainda terá que implementar POST e atualização, com validação e permissões adequadas. Não basta copiar o GET.

7

Liguem o React às rotas e comprovem persistência

Façam a interface chamar a API e atualizar a listagem após cadastrar. Testem o ritual salvar → recarregar (F5) → consultar de novo. Se a informação desaparecer, ainda não foi comprovada persistência.

Exemplo de consulta do React a uma rota própria
const resposta = await fetch('/api/chamados');
if (!resposta.ok) throw new Error('Não foi possível buscar os dados');
const chamados = await resposta.json();
// use o array para atualizar o estado da interface

Não aceito: simular uma inserção com setState e apresentar isso como salvamento definitivo.

8

Acrescentem IA real com uma tarefa delimitada

Escolham uma funcionalidade mensurável, como “transformar a descrição de um chamado em categoria e resumo sugeridos”. O browser chama /api/ia; a rota do servidor acessa a API do provedor com AI_API_KEY e retorna o resultado ao React. Não chamem a API secreta diretamente do browser.

Fluxo didático da IA (não é código executável)
React → POST /api/ia → validação → provedor IA → JSON → revisão humana

Não armazenar ou executar automaticamente instruções perigosas do modelo. Ao usar dados do banco como contexto, enviar só campos necessários e fictícios.

Qualquer provedor de IA verdadeiro é permitido se respeitar segurança e limites de uso; não é necessário treinar modelo.

9

Documentem SQL, índice e EXPLAIN

No banco de demonstração, executem duas consultas relevantes e registrem os resultados. Expliquem um índice adicional por necessidade real. O plano antes/depois não precisa mostrar melhoria de tempo em uma tabela pequena; o importante é interpretar com honestidade.

Exemplo de consulta com JOIN e análise de índice
-- Consulta 1: JOIN para mostrar categoria do chamado
SELECT ch.id, ch.titulo, ca.nome AS categoria
FROM chamados ch
JOIN categorias ca ON ca.id = ch.categoria_id;

-- Consulta 2: filtro e agregação para o painel
SELECT status, COUNT(*) AS total
FROM chamados
GROUP BY status ORDER BY total DESC;

-- Analise ANTES de criar o índice (escolha uma consulta relevante)
EXPLAIN SELECT id FROM chamados WHERE status = 'aberto';
-- Crie um índice justificável
CREATE INDEX idx_chamados_status ON chamados(status);
-- Analise DEPOIS e compare o plano
EXPLAIN SELECT id FROM chamados WHERE status = 'aberto';

É normal um PostgreSQL continuar escolhendo leitura sequencial quando a tabela é pequena; isso não invalida o exercício.

10

Publiquem cedo no Vercel e testem a versão online

Conectem o GitHub ao Vercel, selecionem o projeto, confirmem as configurações do framework e cadastrem variáveis em Project → Settings → Environment Variables. Para a aplicação final, marquem Production e, se forem usar previews, também Preview. Criem um novo deployment após alterações nas variáveis.

VariávelOnde colocarVai ao GitHub?

Checklist de produção: (1) home abre; (2) API funciona; (3) grava; (4) F5 mantém; (5) IA responde; (6) estados de erro aparecem; (7) mobile funciona. Um build verde sozinho não prova o sistema.

Documentação oficial das variáveis do Vercel e guia oficial de variáveis do Next.js.

07 / Prints e comprovações

Print sozinho não é prova completa

Cada evidência precisa trazer a captura legível, a legenda e uma explicação técnica: o que foi feito, como foi feito e o que o resultado comprova.

E1 · Projeto e histórico

Print do GitHub com pastas essenciais, README e commits de integrantes diferentes.

Explique: como o grupo dividiu tarefas e versionou a evolução.

E2 · Persistência

Cadastro pela interface + consulta real no banco após F5.

Explique: que requisição foi feita e em que tabela o dado ficou salvo.

E3 · Integridade e SQL

Diagrama ou tabelas com FKs; consulta JOIN com resultado real.

Explique: por que as tabelas se relacionam e o que a consulta mostra.

E4 · Índice e plano

SQL do índice e capturas EXPLAIN antes/depois.

Explique: por que o índice foi criado e o que realmente mudou (ou não).

E5 · IA real

Interface com prompt/entrada pertinente e saída do provedor, sem revelar tokens.

Explique: benefício concreto, percurso servidor e limites.

E6 · Produção e qualidade

URL Vercel aberta, celular/responsividade e tratamento de erro ou loading.

Explique: como verificaram que produção funciona, não apenas localhost.

Se o deploy der erro — diagnósticos por sintoma

O que apareceO que conferir, nesta ordem
Funciona local, falha no VercelLogs da função; configuração da framework; variáveis em Production; novo deploy após mudança.
Banco responde “undefined” ou conexão falhouDATABASE_URL no backend, cópia correta da string, tabelas criadas no banco da produção.
IA devolve 401/403Validade/permissão da chave e endpoint/provider; checar log servidor sem exibir a chave.
IA devolve 429Quota/limite; mostrar erro amigável; não repetir chamadas em loop.
API 404 / fetch falhaRota publicada, caminho exato e URLs relativas; em front e back separados verificar CORS e backend online.
Dados desaparecem no F5Verificar se há salvamento real no banco, se a listagem lê da API e se o banco correto foi usado.
Senha apareceu no GitHubRevogar/rotacionar imediatamente; remover das versões e corrigir permissões. Só apagar o arquivo do último commit não basta.
Antes de enviar: abram o endereço público em uma aba anônima (sem autenticação local), usem dados fictícios, testem um cadastro, um JOIN/consulta, a IA e a versão celular. Se o sistema só funciona na máquina de um colega, a entrega ainda não está pronta.
